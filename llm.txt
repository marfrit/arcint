# arcint

> Narrow LLM inference engine for Intel Arc GPUs (A770 16 GiB, B60 24 GB).
> Serves the hybrid GatedDeltaNet/attention Qwen family: Qwen3.6-27B-A3B-Coder,
> Qwen3.6-35B-A3B, Qwen3.8-27B (dense) and Qwen3.8-Flash-Next (512-expert MoE).
> OpenVINO is the compiler and kernel library, with a published GPU-plugin
> patch series; arcint owns scheduling, the paged KV cache, the GDN
> recurrent-state ledger, prefix caching, admission by measured reservation,
> MoE expert placement across card and host, speculative decoding, sampling
> and HTTP serving. MoE-beyond-VRAM design follows the expert engines Strata
> and FreeToken (docs/campaigns/research-reference-audit.md); the adaptive
> expert cache and its miss split follow Strata alone.

## Status

Release 0.5.5 (2026-10-04). Runtime dependency: marfrit-openvino +p25, the
pinned OpenVINO nightly 71640275 with patches 0003-0074
(contrib/packaging/marfrit-openvino/patches/); +p27 (0076-0077) for the
Flash-Next tier's opt-in switches MOE_CPU_TIER_ADAPTIVE and MOE_DOORBELL.
Two engines: OpenVINO (default, production) and libllama (--engine llama
--gguf, llama.cpp bed0a85 with contrib/llama.cpp/patches 0001-0014, ggml's
OpenCL backend). The libllama engine decodes faster with the GGUF's MTP
head. With f16 KV the dense model serves 122,880 tokens on the B60, while
the coder's Q4_K_M weights leave it ~16k on the A770 (measured-here). It has no shared
prefix cache yet, so the services stay on OpenVINO (README "Two engines"). Open work is one document per
campaign under docs/campaigns/ (README there: rules, template, index).
Next: 8-bit and 8:4 KV in the libllama engine's OpenCL attention kernels,
an IQ3_XXS-mixed coder GGUF, a prefix cache; multi-draft MTP for
Flash-Next; prefill on the GPU.

## Correctness rule (operator, 2026-10-01; CLAUDE.md, DESIGN 3.4 amended 2026-10-01)

- Correctness is judged at the answer: the answers stay right (facts,
  needle, task battery); the candidate's mean KL against the reference is at
  most 0.03 nats worse than the baseline arm's on the same card and window;
  argmax agreement drops by at most 1 point.
- Bit-identical output across configurations, placements, timing or request
  history is not required. Integrity checks on copied data (expert stores,
  slots, staged tables) stay exact.
- Byte-equality cells in the suites (cache, chunking, lanes, speculation)
  are tripwires: a red one is reported, not a veto.
- An adaptive expert tier together with --prefix-cache-mib > 0 is
  admissible under this rule. The load-time refusal in code
  (tier_prefix_cache_decision, src/config.cpp) is owed a change.

## Contracts

- HTTP: POST /v1/chat/completions, POST /v1/completions (OpenAI-compatible,
  SSE streaming; /v1/completions also takes token-id prompts), GET /health,
  GET /props, GET /v1/models. No UI. /health and /props publish the lanes and
  the reservation terms; a refusal quotes them.
- --served-model-name NAME sets the id /v1/models and /props report and a
  completion echoes; --model-id is the allowlist assertion about which
  artifact is accepted. The model object carries id, canonical_id,
  answers_to, n_ctx (running), n_ctx_train (artifact ceiling), quant, lanes.
- Console: llama.cpp-style one-line state/timing prints on stderr (load,
  memory map, per-slot prefill/decode rates, cache hits, draft acceptance).
- Context overflow is HTTP 400 with prompt_tokens/n_ctx/overflow. No
  truncation, no context shift (GDN state cannot un-see tokens; operator
  decision, undated in the record).
- A request beyond the lanes waits --queue-timeout S, then gets a 503 with
  the reservation numbers.
- Client disconnect aborts GPU work at the next scheduler boundary.
- Tool calls parsed server-side into OpenAI tool_calls (JSON body and the
  coder's <function=>/<parameter=> XML with schema-driven coercion);
  deterministic call ids; never executed; no tools declared = raw text.
- Sampling defaults per allowlist entry (Qwen family card); operator flags
  override them, request fields override both; /props names the provenance.
- Security: no authentication, permissive CORS, no TLS. LAN or a reverse
  proxy only.

## Model input

- OpenVINO IR directory validated against the allowlist
  (src/core/model_registry.cpp, models/allowlist-raw.json): language model,
  text embeddings, tokenizer/detokenizer IRs, config.json, chat template.
  VLM exports: the vision tower is reported at load and never loaded
  (--vision is refused). Text-only serving, and no multimodal, Anthropic
  Messages adapter or local CLI, is an operator decision, undated in the
  record.
- --gguf FILE --model DIR: a GGUF of the same architecture on the IR as
  topology template; K-quant rows (Q4_K, Q5_K, Q6_K, Q8_0) repacked into the
  runtime's compressed form or decoded natively in the plugin kernel
  (--gguf-mode mixed|repack|native). docs/design-gguf-native.md.
- Serving-shape artifacts exported from a GGUF
  (tools/export_serving_artifact.py, tools/q4e/): Flash-Next (qwen4_exp) and
  Qwen3.6-35B-A3B (qwen3_5_moe) with expert bodies in the checkpoint's own
  block formats (IQ2_S, IQ3_XXS, IQ4_NL, IQ4_XS, Q8_0) and dense projections
  in Q8_0/Q6_K-exact u8/i8 form (--dense-q8, --dense-u8). Flash-Next's
  n-gram embedding table is read per forward from the GGUF into a bounded
  staging buffer (--ngram-gguf).
- Allowlist ids: qwen3.6-27b-a3b-coder, qwen3.6-35b-a3b, qwen3.6-35b-a3b-mtp,
  qwen3.8-27b, qwen3.8-27b-intel-int4, qwen3.5-2b, the qwen3.8-flash-next-*
  ladder (d4, d4qsa, d12, d12r, seg12, full, d48g, d48n, d48s, d48p2, d48s2,
  d48q8, d48q8qsa) and the qwen3.6-35b-a3b-native-* ladder (d4, d40, d40f16,
  d40packed, d40packed2, d40packed-u8, d4packed, d4packed-u8). Each entry's
  status string in the registry names what was measured on it.

## Mechanisms

- Paged executor is the served path (PagedAttention + paged GDN kernels);
  the stateful executor stays behind --no-paged as the reference.
- Admission by measured reservation: weights and graph from
  GPU_MEMORY_STATISTICS, the activation peak probed upward chunk by chunk,
  GDN slab, KV per token, a stated margin (--fit-margin-mib). Omitting
  --n-ctx adopts the auto-fit depth; an explicit --n-ctx is verified, never
  lowered. --fit-ledger-dir persists the probed terms across starts.
- GDN state checkpoints are block-aligned with KV pages; prefill chunks and
  snapshots sit on an absolute grid from position 0; the prefix index is
  keyed 128-bit block hashes verified token by token; --cache-host-mib parks
  evicted prefixes in host RAM.
- Lanes (--parallel N): one process, per-lane InferRequests, GDN rows and
  block tables over a shared refcounted page pool, a FIFO turnstile around
  graph executions (the plugin pools intermediate buffers per compiled
  model).
- Logits are sliced to the last token before the LM head; attention KV is
  stored at the --paged-kv precision (u8 default; f16, i8, u4, i4, and
  asymmetric KEY:VALUE pairs).
- Speculative decoding (greedy): the Qwen3.8 MTP head (--mtp on;
  tools/export_mtp.py reconstructs it from the checkpoint's mtp.* tensors),
  the DFlash2 block drafter (--dflash, seven drafts per verify pass,
  optionally on another card), prompt lookup (--draft N). A draft is accepted
  only where it equals the sampler's own pick for that row; rollback on the
  paged path is block-table and state-row arithmetic.
- MoE expert placement beyond VRAM: --offload-ratio N keeps 100-N percent of
  each layer's experts in device slots; --moe-cpu-tier computes the rest on
  the host CPU (AVX2 decoders for the native formats, a quantised-domain dot
  for decode); --moe-per-expert-dispatch runs resident experts as
  per-expert GPU kernels; the plugin's MOE_CPU_BANK_BYTES fills a host RAM
  bank with the tier's experts at load; MOE_CPU_TIER_SEED pins the resident
  set from a routing census; ARCINT_MOE_DEVICE_POOL_BYTES bounds the device
  slot pool. On a fully resident native MoE pool a device kernel writes the
  decode step's expert pair table from the router output (patch 0067).
- Qwen Sparse Attention (Flash-Next, --qsa export, qwen3.8-flash-next-d48q8qsa):
  served with a compressed block-key indexer cache; non-default; n_ctx <=
  32768. It still refuses --parallel > 1, the prefix cache and paged
  speculation; each refusal is owed a change (Strata appends to the indexer
  at commit, src/core/verify.cpp:990; DESIGN 8.9).
- Compiled-blob disk cache in weightless mode with absolute weight paths
  (works around openvino#37607).

## Divergence policy (DESIGN 1.1)

Smallest sufficient divergence from upstream OpenVINO, in order: an upstream
PR; a numbered, PR-shaped patch series applied at build time
(contrib/packaging/marfrit-openvino/patches/, README there names each
patch); a maintained fork only with a stated reason and exit condition.
Whatever is carried is published.

                            the model's own maximum. --n-ctx 0 (typed) is
                            NOT the same as omitting the flag: it asks

                            against the fit like any other explicit value --

                            (default: 2048; bounds activation memory)

                            "f16" mean exactly what they always did). A colon pair
                            asks for asymmetric precision (M8) and is refused unless
                            the compiled paged model actually carries the requested
                            widths per side.
                            u8 is 11.3 KiB/token against f16's 20.0, which
                            is what makes two lanes at depth fit. It is the
                            default because it is the setting that does not
                            refuse, not because it is faster -- f16 wins on

                            whole difference lands there

## Build

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build
ctest --test-dir build --output-on-failure -L unit
./build/arcint --stub --port 8090 -v

-DARCINT_OPENVINO=ON builds the serving backend against the pinned OpenVINO;
-DARCINT_WERROR=ON is warning-clean; ASan+UBSan clean on x86_64 (ASan aborts
at startup on aarch64).
