# arcint

> Intel Arc LLM inference engine, deliberately narrow (Arc A770 16 GiB, Arc
> Pro B60 24 GB), with an OpenAI-compatible HTTP API. Serves an allowlist:
> the hybrid GatedDeltaNet/attention Qwens Qwen3.6-27B-A3B-Coder and
> Qwen3.6-35B-A3B (qwen3_5_moe), Qwen3.8-27B dense (qwen3_5) and Qwen3.8
> Flash-Next (qwen4_exp), plus Cydonia 24B (llama) for writing. Two engines:
> OpenVINO with a published GPU-plugin patch series on a pinned nightly, and
> libllama (llama.cpp with arcint's OpenCL kernels for Intel). arcint owns
> scheduling, the KV cache and the GDN recurrent state, prefix caching and
> context checkpoints, admission, expert placement, speculative decoding,
> sampling and HTTP serving. NInfer philosophy (specialize, then be honest
> about numbers), Intel substrate.

## Contracts

- HTTP: POST /v1/chat/completions, POST /v1/completions (OpenAI-compatible,
  SSE streaming, token-id prompts on /v1/completions), GET /health, GET
  /props, GET /v1/models. No UI. /health and /props publish the lanes, the
  reservation terms and the served cache block; a refusal quotes them.
- The served NAME and CONTEXT are contracts with a discovering proxy (DESIGN
  4.2): --served-model-name sets what /v1/models and /props report and what a
  completion echoes; --model-id stays the allowlist assertion. The model
  object carries n_ctx (what the process runs with) and n_ctx_train (the
  artifact's ceiling), plus quant, lanes, canonical_id.
- Console: llama.cpp-style one-line state/timing prints on stderr, with where
  each request's time went (graph, embed, sample, emit, wait for the other
  lane).
- Model input: an OpenVINO IR directory validated against a compiled-in
  allowlist (architecture/template/tokenizer hashes, geometry, weight byte
  count); a GGUF opens on top of one (--gguf); serving-shape artifacts are
  built from GGUF shards (tools/export_serving_artifact.py). Anything else is
  rejected at load.
- Hard invariant (DESIGN 3.4, gated): for any prompt and any cache state,
  greedy output is byte-identical to a cold run, per lane with the other lane
  active, and independent of the process's own request history. NOT claimed
  across chunked/unchunked prefill or speculation on/off: advancing the state
  by two tokens in one forward differs from twice by one (GDN scan, matmul
  tiling), so any change to how a sequence is split can flip a near-tie. Those
  comparisons are reported; determinism at a fixed configuration and non-zero
  draft acceptance are gated. Prefill chunks and cache checkpoints sit on one
  absolute grid so warm and cold runs see the same split.
- Context overflow = HTTP 400 with prompt_tokens/n_ctx/overflow. No
  truncation, no context shift (a GDN recurrent state cannot un-see tokens).
- Admission: a lane is a memory reservation; every term measured (weights
  after compile, activations by probe forwards, GDN rows, KV at the served
  precision, drafter state, expert slots on two ledgers, one policy margin).
  What does not fit is refused at startup with every term; a request beyond
  the lanes is a 503 with the numbers (--queue-timeout S restores queueing).

## Key design points

- Paged executor is the served path (SDPAToPagedAttention: paged KV ports,
  GDN state tables on their own block table); the stateful executor stays
  behind --no-paged as the equivalence reference. Serving-shape IRs are paged
  only.
- Two lanes in one process (--parallel 2): per-lane InferRequests, GDN rows
  and KV block tables over a shared refcounted page pool; a FIFO turnstile
  orders graph executions (a correctness mechanism: the GPU plugin pools
  intermediates per compiled model); sequences are never batched into one
  graph call.
- Prefix cache: keyed 128-bit block hashes with token verification; a hit
  restores KV pages by reference and the GDN checkpoint row together; evicted
  entries can park in host RAM (--cache-host-mib) and come back byte-exact.
- KV precision (--paged-kv KEY[:VALUE]): u8 default (11.3 KiB/token on the
  coder, the setting that does not refuse); u8:i4 = +28% auto-fit context,
  u8's prefill rate from +p6 (micro-SDPA, values unpacked in registers); f16
  faster at depth, costs prefix-cache reserve; u4 a capacity lever only.
- Speculation (greedy only): a draft is accepted only if it equals the
  sampler's pick from the verify pass's row; rollback on the paged path is
  checkpoint-row promotion, zero bytes. MTP head reconstructed by
  tools/export_mtp.py ((1+w) norms, per-head interleaved q/gate, sigmoid
  gate); DFlash2 via tools/export_dflash.py; n-gram drafter. Drafters' rotary
  kept f32 (f16 overflowed at 65,504), MTP state charged in the reservation.
- MoE routes: fused int4 resident; --offload-ratio with a device-resident
  slot pool; --moe-cpu-tier computes capacity misses on the CPU under a static
  residency partition (patch 0018; census-seeded with 0046) so output stays
  history-independent; --moe-per-expert-dispatch computes only the routed
  experts with per-expert kernels decoding the checkpoint's own blocks
  (IQ2_S, IQ2_S-packed, IQ3_XXS, IQ4_NL, Q8_0), all-resident at
  --offload-ratio 0 (the 35B route above: batched and expert-grouped
  launches, several rows per load, the IQ2_S gate/up on the matrix unit with
  exact operands, decode routing on the device).
- GGUF (--gguf FILE --model DIR): the file's K-quant rows replace the
  template IR's projections; --gguf-mode mixed (default: Q4_K repacked into
  the runtime's compressed form within a measured bound, 1/64 step for Q4_K;
  Q5_K/Q6_K as the file's rows through a K-quant kernel), repack, native;
  --gguf-mins exact|split|shared|nibble; --gguf-q6k aligned|file;
  --gguf-embed file|template; --gguf-check once|always; f16 activations on a
  GGUF-opened model.
- Fit: --n-ctx omitted adopts the maximum admissible depth (auto-fit, audited
  and trimmed at allocation); --n-ctx given is verify-only, never lowered;
  --prefix-cache-reserve PCT keeps spare pages under auto-fit;
  --fit-ledger-dir persists the probed terms to skip load-time probes.
- Tokenizer + chat template ship in the artifact (hashes pinned);
  incremental UTF-8-safe detokenization; reasoning split into
  reasoning_content; tool calls parsed into OpenAI tool_calls (both Qwen wire
  forms), never executed; no tools declared = parser never runs.
- Sampling: host-side, penalties before the greedy decision, seeded and
  logged; defaults request > operator flags > artifact > model card, with
  provenance on /props.
- Divergence policy (DESIGN 1.1): smallest sufficient divergence — upstream
  PR, else a numbered PR-shaped patch series applied at build time and
  published, else (last resort) a fork with an exit condition. The per-patch
  record is contrib/packaging/marfrit-openvino/patches/README.md.
- Per-card facts: the B60's GDN state output is one-ulp nondeterministic run
  to run on the served Flash-Next path (open, reported upstream); the A770 is
  bit-identical, so floors and byte-identity are read there.

## Layout

- README.md: intro, building, the measured tables, supported models and
  formats.
- FURTHER-READING.md: the fuller measured record, scope, artifact provenance
  and calibration, features, non-goals, status, deploying, why-not-X.
- DESIGN.md: the current state — architecture (§3), invariants (§3.4, §3.8),
  serving (§4), gates (§5, the generated acceptance row in §5.1), evidence
  against the upstream pipeline layer (§6), milestones and the standing value
  of every subsystem (§7, with the record index §7.0.2), open questions (§8).
- CHANGELOG.md: per-release changes and the runtime (patch level) each
  release depends on; the Debian changelogs under contrib/ are the package
  record.
- DEVELOPMENT.md: hardware, dependencies, how to run the suites.
- contrib/packaging/: the Debian recipes for arcint and the patched runtime,
  with the patch series and its per-patch record; patches/ mirrors the series.
- contrib/systemd/: the two deployed units as examples.
- models/allowlist-raw.json: raw IR metadata, the allowlist's provenance.
- src/: config, util/, core/ (model_registry, sampler, stop, toolcall, chat,
  prefix_cache, block_pool, turnstile, gguf reader/dequant/repack), exec/
  (backend interface, stub, backend_ov, fit arithmetic, graph rewrites, the
  n-gram staging), api/, http/.
- tools/: exporters (export_mtp.py, export_dflash.py,
  export_serving_artifact.py and q4e/), measurement instruments, the
  acceptance manifest generator.
- tests/: `unit` (what bare ctest runs, device-free: the hand-rolled harness
  where a skip is a failure unless named, roundtrip.sh, concurrency/stress.sh,
  the acceptance enumeration's own checks) and `acceptance` (card-requiring
  cells enumerated in tests/acceptance/cells.json and run by
  tests/acceptance/run.py; equivalence/run.sh and concurrency/run.py are its
  runners; the Prüfstand is the external cell). docs/release-checklist.md and
  the DESIGN §5.1 acceptance row are generated from that enumeration.
- docs/: the release checklist, the SOP for card windows, and the few design
  notes the tooling cites; everything else on the development branch.
- third_party/: cpp-httplib, nlohmann/json, single headers.

## Build

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build
ctest --test-dir build --output-on-failure -L unit
./build/arcint --stub --port 8090 -v

-DARCINT_OPENVINO=ON builds the served executor against the patched runtime;
-DARCINT_WERROR=ON is warning-clean. Clean under ASan+UBSan with
-fno-sanitize-recover, but ASan must run on x86_64: it aborts at startup on
aarch64.

## Provenance

Design grounded in 2026-08 measurement campaigns on this hardware: OpenVINO
60 t/s vs Vulkan 7.9 t/s on the B60 for the same checkpoint; SE calibration
degenerates greedy on dense Qwen3.8; OV GenAI's CB path diverges from its
stateful path under greedy (upstream issue openvino.genai#4367, CI equality
test skipped since 2025-02); OV model-cache import bug and workaround
(openvinotoolkit/openvino#37607). Performance bar: beat 60 t/s (27B q4, B60)
while holding the equivalence invariants — held at 66.5 t/s.
